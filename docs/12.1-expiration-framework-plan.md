# 12.1 Expiration Framework — build plan

Status: **PLAN (not yet built).** Green-lit to build after review. Powers the AD **icon**
indicator first (the expiry-alert border/tint we've been testing), then generalises.

## 1. Goal & principles

Replace the dead pre-12.1 "Expiring" system with a **reusable, secret-safe expiration
framework** — one engine + one GUI helper — so every consumer (AD icon/square, and later the
frame-level health-bar / border indicators) drives expiration the same way, with **no
per-feature hand-rolling**.

- **Secret-safe only.** Remaining time is secret in 12.1, so nothing reads it in Lua. All
  reveal/colour decisions are baked into a native `SetDurationText` band formatter and
  evaluated C-side (the `|T` reveal we proved live 2026-07-20).
- **Mirror the legacy two-layer shape** the codebase already knows: a **background/engine
  helper** + a **shared GUI helper** (see §2), so it reads familiarly.
- **Engine/helpers, never copies** (per the standing rule). The icon code we built inline is
  extracted INTO the engine; the icon then *calls* the engine.

## 2. Legacy architecture we're mirroring (to be marked PRE-12.1, then deleted)

The old DF expiration system was two layers:

- **GUI helper (shared, config-driven):** `GUI:CreateExpiringControls(group, dbTable, opts)`
  (`GUI/GUI.lua`), driven by `opts.keys` (which DB keys to bind) + `opts.include` (which rows
  to show). Consumers called it through the local `AddExpiringBorderGroup` wrapper
  (`AuraDesigner/Options.lua`), plus `CreateExpiringThresholdRow` /
  `CreateExpiringDurationPriorityRow`.
- **Background engine:** the ~3 Hz **expiring ticker** that read each aura's remaining time
  and recoloured/pulsed the border/tint — the shared OnUpdate border driver in
  `Frames/Border.lua`, colour-curve helper in `Features/Highlights.lua`, alpha in
  `Features/ElementAppearance.lua`, and `DF:LightweightUpdateExpiringBorderColor` /
  `…TintColor` in `Core.lua`.

**All of the above is dead on 12.1** (ticker can't read the secret timer; the GUI is frosted
with a permanent `"limitation"` block). It stays only as reference.

## 3. New architecture

Same two layers, secret-safe:

```
  [ GUI helper ]  GUI:CreateExpirationControls(group, dbTable, opts)
        keys{...} + include{...}  ->  Mode / Style / Colour / Opacity /
        Match / Inset / Threshold / Anchor / Offsets   (grey + hide policy)
                         |  reads/writes the same DB keys
                         v
  [ Engine ]      DF.Expiration   (Features/Expiration.lua)
        DF.Expiration:BuildCompanion(unit, map, cfg, geometry, mine) -> config|nil
        DF.Expiration:StructSig(cfg, geometry)  -> rebuild-gating string
        DF.Expiration:BuildPreview(cfg, geometry) -> {payload, anchor, ...}
        (internally: band formatter + |T escape + colour static/by-time)
                         |  returns a 1-slot companion container config
                         v
  [ Consumer ]    AD icon factory: compute geometry (iconSize x 0.75, anchor
        CENTER), read cfg keys, attach the companion. NO reveal logic of its own.
        (Future) health-bar / frame-border: same call, bar/frame geometry.
```

### 3a. Engine — `DF.Expiration` (new file `Features/Expiration.lua`)

Extract today's inline icon code (`GetExpiryBorder*` / `GetExpiryAlert*` in `Features/Auras.lua`
+ the companion/`effectiveAlertSize`/`alertElemStructKey`/`buildAlertPreview` in
`AuraDesigner/Factory.lua`) into ONE engine with a geometry-agnostic API:

- **`cfg`** (the settings block, read from any DB): `mode` (OFF / TEXT / GLYPH / **BORDER** /
  **TINT**), `threshold`, `text`, `glyph`, and for BORDER/TINT: `colorMode` (STATIC/BYTIME),
  `color`, `alpha`, plus placement (`matchIcon`, `inset`, `manualSize`, `anchor`, `offsetX`,
  `offsetY`). **BORDER** additionally has `thickness` (THIN/MEDIUM/THICK — a frame outline).
  **TINT** is a solid fill wash (no thickness). The engine picks the `|T` texture by mode:
  BORDER → the frame art for its thickness; TINT → the solid fill art.
  - **Border mode is NOT renamed** and stays frame-only; **Tint is its own mode** (its own
    entry in the Expiry Alert dropdown), not a "Fill" style hidden under Border. One companion
    = one `|T`, so they're either/or for now (both-at-once = a 2nd companion, future).
- **`geometry`** (the target the reveal overlays): `baseSize` (icon side) for icons/squares;
  later `width`/`height` for a health-bar wash. The engine does the ×0.75 calibration + inset
  + match here, so callers never repeat it.
- **API:**
  - `DF.Expiration:BuildCompanion(unit, map, cfg, geometry, mine)` → a 1-slot container
    config (the hidden aura button + its duration-text `|T` reveal), or `nil` when off. This
    is the single reusable seam — the consumer just attaches it.
  - `DF.Expiration:StructSig(cfg, geometry)` → rebuild-gating string (today's
    `alertElemStructKey`).
  - `DF.Expiration:BuildPreview(cfg, geometry)` → `{payload, anchor, offsetX, offsetY, size,
    alpha, font}` for the editor canvas.
  - Keep `DF:GetExpiryBorderEscape` / the `EXPIRE_BORDER_TEXTURES` map / the band builders as
    engine internals (moved from Auras.lua).
- **No ticker.** The "background" work is producing the band ruleset once; Blizzard's C-side
  binding is the runtime driver. That is the 12.1-safe replacement for the old ~3 Hz ticker.

### 3b. GUI helper — `GUI:CreateExpirationControls(group, dbTable, opts)` (in `GUI/GUI.lua`, next to the legacy one)

Extract today's `AddExpiryAlertControls` (`AuraDesigner/Options.lua`) into a shared helper
shaped like `CreateExpiringControls`:

- `opts.keys = { mode, threshold, text, glyph, anchor, offsetX, offsetY, size, colorMode,
  color, style, alpha, matchIcon, inset }` — bind to whatever the consumer stores.
- `opts.include = { text, glyph, ... }` — a health-bar consumer can drop TEXT/GLYPH and keep
  only BORDER/TINT, for instance.
- Owns the **grey vs hide** policy we agreed: **hide** rows that don't belong to the mode
  (Alert Text off-mode, Glyph off-mode, Anchor in Border), **grey** rows inactive-but-
  available within the mode (Border Colour under By-Time, Size under Match-Icon). Uses the
  group's `hideOn` + `LayoutChildren` + `dfAD_ReflowWidgets` reflow (the CreateBorderControls
  precedent) so hidden rows collapse.
- Callbacks: `refresh`, `refreshStates` (mirrors the legacy helper's signature).

### 3c. Consumer rewire (AD icon first)

- `AuraDesigner/Options.lua`: the icon (and square) card calls
  `GUI:CreateExpirationControls` with the `expiryAlert*` keys instead of the inline
  `AddExpiryAlertControls`.
- `AuraDesigner/Factory.lua`: `buildAlertCompanionConfig` / `buildAlertPreview` call
  `DF.Expiration:BuildCompanion` / `…Preview`; the struct sig uses
  `DF.Expiration:StructSig`. The inline branches move into the engine.
- **DB keys unchanged** (`expiryAlert*` + `expiryAlertBorder*`) → no migration, no profile
  churn (change-baseline rule respected).

## 4. Config schema (unchanged keys, now engine-owned)

`expiryAlertMode`, `expiryAlertThreshold`, `expiryAlertText`, `expiryAlertGlyph`,
`expiryAlertAnchor`, `expiryAlertOffsetX/Y`, `expiryAlertSize`, and BORDER:
`expiryAlertBorderColorMode`, `expiryAlertBorderColor`, `expiryAlertBorderMatchIcon`,
`expiryAlertBorderInset`, `expiryAlertBorderAlpha` — **shared by BORDER and TINT** (either/or
modes). `expiryAlertBorderThickness` holds **THIN/MEDIUM/THICK only** (frame outline; Tint is a
mode now, not a `FILL` style) — so the key name is accurate and needs no rename. The current
uncommitted "Style: Fill" build gets reworked into the TINT mode during Stage 2.

## 5. Legacy teardown (mark now, delete after the framework lands)

Tag each with `-- PRE-12.1 (dead: remaining-time secret) — delete with the expiration
framework`. Do NOT delete until the new engine ships (so the frosted panels keep rendering
harmlessly meanwhile):

- `GUI/GUI.lua`: `CreateExpiringControls`, `CreateExpiringThresholdRow`,
  `CreateExpiringDurationPriorityRow`.
- `AuraDesigner/Options.lua`: `AddExpiringBorderGroup`, `AddExpiringBorderGroup(...)` call
  sites, the `expiringGroup` limitation blocks.
- `Core.lua`: `LightweightUpdateExpiringBorderColor`, `…TintColor`.
- `Frames/Border.lua`, `Features/Highlights.lua`, `Features/ElementAppearance.lua`: the
  expiring-ticker / colour-curve / alpha paths.
- `Config.lua` / `TYPE_DEFAULTS` / `ExportCategories.lua`: the `expiring*` keys (keep the
  frosted controls reading them until deletion).

## 6. Build stages (each its own commit)

1. **Engine extract.** New `Features/Expiration.lua`; move the reveal formatters + companion
   builders out of Auras.lua/Factory.lua behind the geometry-agnostic API. Icon behaviour
   byte-identical (pure refactor). Verify in-game unchanged.
2. **GUI helper extract.** `GUI:CreateExpirationControls`; icon/square cards call it. Same
   controls, now shared. Apply the hide-vs-grey policy.
3. **Mark legacy PRE-12.1.** Tag every surface in §5 (no deletion yet).
4. **(Optional, later) delete legacy** once the framework is proven across a PTR cycle.
5. **(Future) new consumers.** Health-bar wash + frame-border overlay call the same engine
   with bar/frame geometry — a companion per frame-level indicator (see the border/health-bar
   verdict). Each is a small increment on the shared engine, no new reveal logic.

## 7. Decisions (settled) + remaining open items

**Settled:**
- **Name:** `DF.Expiration` / `Features/Expiration.lua`; GUI helper `GUI:CreateExpirationControls`.
- **Border mode not renamed**, frame-only. **Tint is its own mode** (own dropdown entry), not a
  Fill style under Border.
- **Hide-vs-grey is a framework rule** (owned by the GUI helper): a setting that does NOT belong
  to the current mode is **HIDDEN** (row collapses via `hideOn` + reflow); a setting that
  belongs but is **disabled/inactive** is **GREYED** via the standard GUI grey-out
  (`SetEnabled`, which dims per the GUI-rework convention — never a bespoke dim). Examples:
  Text/Glyph/Anchor hidden in BORDER/TINT; Style hidden in TINT; Border Colour greyed under
  By-Time; Size greyed under Match-Icon.
- **Key rename moot:** `expiryAlertBorderThickness` holds THIN/MEDIUM/THICK only now — accurate.
- **Tint opacity:** keep the Fill art at 50% so TINT's default (Opacity 1.0 × 50% art) is a
  50% wash — the good default we tested — while Opacity dials it down. TINT effectively caps at
  50% (deliberate: a wash should never fully obscure the icon). BORDER art stays opaque so its
  Opacity spans full 0–100%. One shared `expiryAlertBorderAlpha` key, default 1.0.

**Remaining open:**
- **Border + tint together** on one indicator needs two companions (one `|T` per band string).
  Ship either/or first; revisit only if wanted.
- **Hold depth:** build the engine + icon (+ square, which shares the card) now; gate the
  health-bar / frame-border consumers until a PTR cycle confirms no better native expiry signal
  appears (re-check list in the expiration state-of-play notes).

## 8. Non-goals (permanent 12.1 casualties — do NOT try to revive here)

Smooth/looping expiry animation, alpha pulse, bounce, thickness-by-time — all need a
remaining-time read or per-frame button-child animation, both impossible (source-confirmed: no
expiring callback in the container API). The framework's ceiling is: static reveal +
time-stepped colour + opacity, plus native cooldown Flash-on-Expiry (already shipped).
